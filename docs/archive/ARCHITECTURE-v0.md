# AgentShield Architecture

## Vision

AgentShield is an Internet Trust Protocol.

AgentShield continuously establishes identity,
preserves memory, infers intent, computes trust,
and enables autonomous access decisions.

Core Flow:

Identity
↓
Memory
↓
Intent
↓
Trust
↓
Decision

---

## Core Principle

AgentShield does not evaluate requests.

AgentShield evaluates entities.

The primary entity of the system is Identity.

Requests are events generated by identities.

---

## Domain Model

Tenant
 ├─ ApiKey
 └─ Identity
      └─ Event

---

## Identity

Represents an internet entity.

Examples:

- Human browser
- API client
- AI agent
- Device
- Service account

---

## Memory

Memory is stored as Events.

Every interaction contributes to the history of an identity.

---

## Trust

Trust is computed from historical behavior.

Trust is not manually assigned.

Trust is earned or lost over time.

---

## Decision

Allow
Challenge
Block

Decisions are outputs.

Trust is the source.

## Technical Decisions

### Prisma Runtime

Date:
2026-06-03

Status:
OPEN

Finding:

Prisma migrations work correctly.

Prisma runtime does not initialize correctly in the
current development environment.

Observed Issues:

- Prisma Client requires adapter configuration
- Adapter API differs from documentation/examples
- Runtime searches for .prisma/client/default
- Generated client does not create expected runtime files

Decision:

Use Prisma for:

- Schema definition
- Database migrations

Use better-sqlite3 for:

- Runtime database access
- Repository layer implementation

Reason:

Current project stage prioritizes rapid development
of Identity, Memory, Intent and Trust systems over
ORM runtime complexity.

Future Re-evaluation:

Revisit Prisma runtime after v1 architecture is stable.
